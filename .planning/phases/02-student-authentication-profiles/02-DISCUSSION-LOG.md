## Session storage

| Option | Description | Selected |
|--------|-------------|----------|
| A — `sessions` table (per-device); force-logout deletes rows for that user | DB-backed sessions; "force logout" = `DELETE FROM sessions WHERE user_id = ?` | ✓ |
| B — Keep PHP file-based sessions; "force logout" flips `users.force_reauth_at` | Every auth check reads the users row; cheaper but doesn't target a specific device | |
| C — A + a `users.is_banned` shortcut that bypasses the sessions table | Banned users get immediate logout across devices with no `DELETE` storm | ✓ |

**User's choice:** A + C
**Notes:** DB-backed sessions make multi-device state observable. The `is_banned` shortcut means banning a user is a single UPDATE, not a DELETE storm.

## the agent's Discretion

The following items were not explicitly decided but follow from locked requirements or are routine implementation choices:
- **Login form layout** — center-aligned card, max-width 400px, email above password, "Register" left and "Forgot password?" right below the form.
- **Rate-limit response shape for non-login state-changing endpoints** — same inline error pattern as login.
- **`/settings` page scope** — theme toggle + logout button; "notification preferences (toast only)" in EXPERIENCE.md is interpreted as "toasts are the only notification channel" not "user has a preference for toasts."
- **The `+50` points stub for email verification** — the verify Action calls a `Points/Service/points_service.php` stub that writes a `points_log` row and updates `users.points`. The stub's signature matches Phase 6's real implementation.
- **Migrations 003..007 content** — `003_sessions`, `004_email_verifications`, `005_password_resets`, `006_student_id_allowlist`, `007_cache_rate`. The planner can confirm or revise the exact file split.

- **Cohort isolation (AD-20)** — single-cohort for MVP; gate at S2 retro.

- **Real email backend** — the flash-toast-with-link pattern in D-02 and D-07 is the simulation.
- **"Remember me" checkbox** — D-04 fixed 7-day refresh-on-activity.
