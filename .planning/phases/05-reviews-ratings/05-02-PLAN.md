# Plan 05-02: Public Profile Aggregation + Listing Modal

## Context

Plan 05-01 ships the WRITE path. This plan (expansion) ships the READ path: when a student views a seller's public profile, the profile now shows real rating aggregation, a 1..5 distribution, the public dispute count, and the paginated list of reviews received. The listing modal also surfaces a compact `★ 4.8 (23 reviews)` row inline next to the seller's tier badge.

Honors CONTEXT.md decisions:
- **D-02** Reviews tab shows reviews RECEIVED by the owner; Phase 5 does not split "buyers rate seller" vs "sellers rate buyer" — the tab shows all reviews the user received, regardless of `reviewer_role`.
- **D-07** `getSummaryForUser` returns `{rating_avg, rating_count, rating_distribution, dispute_count}` from two SQL statements; called from `PublicProfileAction`.
- **D-08** Reviews tab paginated 10/page with Prev/Next.
- **D-09** dispute count column ships now (returns 0 until Phase 7 lands `dispute_status='upheld'` updates); on the listing modal, the count is hidden when 0; on the public profile it's always shown as "0 disputes" so the column's existence is signalled.

- **Reviews tab content size** — A seller with 200 reviews will paginate over 20 pages. The Prev/Next rendering is the same as Phase 3's board pagination. No new risk.
