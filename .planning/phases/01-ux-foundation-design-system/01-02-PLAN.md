## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Mockup HTML | The user opens a static file or a dev-server-served file. No network request beyond the two CDNs (Bootstrap, Inter). No data leaves the browser. |
| localStorage / sessionStorage -> Theme + list-view toggle | The list-view toggle persists the cork vs. plain-grid choice to `sessionStorage.tickettrade.listView`. The theme persists to `localStorage.tickettrade.theme`. No other storage writes in this plan. |
| JS toast -> DOM | `TicketTrade.toast.show` writes a `<div class="toast ...">` to the DOM. The message is a string parameter; the type is one of `success`/`error`/`warning`/`info` (unknown types fall through to `info` and log a `console.warn`). |
| Keyboard -> Component focus order | Tab and Shift+Tab traverse the focusable elements. The skip link is first; the corkboard cards or ticket cards are next; the bottom nav is last. The order is enforced by document order. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-2-01 | Tampering | `tickettrade.components.css` | low | mitigate | Same as T-01-01: the file references design tokens only (verified by the hex-literal grep). A PR that adds a hex literal is rejected by code review. |

| T-01-2-03 | Repudiation | List-view toggle state change | low | accept | Per-session, per-device, not attributable to a user. No audit row needed. |
